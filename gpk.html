Rendering

Projected boundaries take, at each screen pixel, the label with the largest Gaussian-weighted vote of nearby cells; an interface cell votes α for its own label and 1 − α for its competitor.

Gaussian-projected kinetics

Every cell stores an integer grain or phase label φ and a sub-cell position α of its boundary. Nothing diffuse is stored: near a boundary, the indicator of the resident label is smoothed with a Gaussian of fixed width ℓG = 2Δx, and the normal and curvature are read from its gradient and Hessian. The Gaussian is then discarded.

Each time step:

  1. find interface cells and measure n̂ and κ;
  2. evaluate vn = M [ΔG − σ(n̂) κ] from the process model;
  3. average vn over the same pair of labels, so unrelated boundaries at a junction never mix;
  4. move α by vnΔt/Δx; when it reaches zero the cell switches to the neighbouring label, but only if a digital-topology test shows no grain is split or merged;
  5. apply volume-balanced exchanges that smooth staircase artefacts, remove grains smaller than the Gaussian scale, and diffuse solute.

The time step is Δt = Δx / (8 vmax), limited further by diffusion.

This page is a JavaScript port of the C++ code, in 2D and 3D, and follows it step by step. From the same initial grains it reproduces the C++ grain-growth trajectory: in 2D, 4 of 16,384 cells differ after 377 steps; in 3D, 1 of 32,768 cells differs after 100 steps. The C++ code computes in single precision and the port in double, so runs drift apart slowly after that.

In 3D the topology test checks face connectivity on the 3×3×3 block around a cell, the volume-balanced remap runs a second sweep to remove ledges as the C++ code does, and the 19³ Gaussian-Hessian stencil is evaluated as three one-dimensional passes, which gives the same numbers at a fraction of the cost.

Using this page

Sliders change the run immediately. Grid, cell size, seed and initial settings take effect with Reset with these settings.

Click the map to add a grain, nucleus or seed where the model allows it. Hover over a cell to read its values.

3D runs on a cube of up to 96³ cells. The map then shows either a rotatable 3D surface or a slice through the volume; switch between them with the bar at the bottom of the map. Clicking a slice seeds at that depth. A 3D step costs far more than a 2D one, so the smaller grids are the ones to explore with.

Export → Input deck writes a GPK .ini file with the current settings, so a run can be repeated with the full C++ code on larger grids.

Keys: Space run/pause, S step, R reset.
